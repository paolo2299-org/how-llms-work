The inference-only model already contains every learned component we need: token and position embeddings, transformer blocks, a final LayerNorm, and the vocabulary projection. Pre-training does not add another kind of neural-network layer.

What changes is how data moves through those components. Training processes several sequences at once and needs a next-token prediction at every position, rather than only the final prediction for one prompt.

The shape changes introduced by the trainable model
Value Inference-only model Trainable model
Token IDs (tokens,) (batch, tokens)
Token vectors (tokens, model_dim) (batch, tokens, model_dim)
One attention calculation (heads, tokens, head_dim) (batch, heads, tokens, head_dim)
Vocabulary logits (vocabulary,) (batch, tokens, vocabulary)
The key idea: the learned matrices keep the same shapes. The new batch axis groups independent sequences, while the token axis is retained so every position can contribute to the training loss.

1. Embeddings accept a batch

The inference-only embedding receives one sequence. The trainable version requires a two-dimensional tensor and reads the sequence length from its second axis:

def forward(self, token_ids):
    if token_ids.ndim != 2:
        raise ValueError(
            "token_ids must have shape (batch_size, sequence_length)"
        )

    sequence_length = token_ids.size(1)
    if sequence_length > self.max_sequence_length:
        raise ValueError(
            f"input has {sequence_length} tokens, but the maximum is "
            f"{self.max_sequence_length}"
        )

    positions = torch.arange(
        sequence_length,
        device=token_ids.device,
    )
    token_vectors = self.token_embedding(token_ids)
    position_vectors = self.position_embedding(positions)

    # PyTorch broadcasts the position vectors across every sequence in the
    # batch. Each sequence therefore uses positions 0, 1, 2, and so on.
    return token_vectors + position_vectors

token_vectors has shape (batch, tokens, model_dim). The position lookup has shape (tokens, model_dim); PyTorch broadcasts those same positions across every sequence in the batch.

2. Attention preserves the batch axis

The attention calculation itself is unchanged. The only new concept is choosing the correct axes when splitting token vectors into heads and joining them again:

batch_size, num_tokens, _ = x.shape

queries = self.W_query(x)
keys = self.W_key(x)
values = self.W_value(x)

queries = queries.view(
    batch_size,
    num_tokens,
    self.num_heads,
    self.head_dim,
).transpose(1, 2)
keys = keys.view(
    batch_size,
    num_tokens,
    self.num_heads,
    self.head_dim,
).transpose(1, 2)
values = values.view(
    batch_size,
    num_tokens,
    self.num_heads,
    self.head_dim,
).transpose(1, 2)

attention_scores = queries @ keys.transpose(-2, -1)

mask = torch.triu(
    torch.ones(
        num_tokens,
        num_tokens,
        dtype=torch.bool,
        device=x.device,
    ),
    diagonal=1,
)
attention_scores = attention_scores.masked_fill(mask, float("-inf"))

attention_weights = torch.softmax(
    attention_scores / self.head_dim**0.5,
    dim=-1,
)

context = attention_weights @ values
context = context.transpose(1, 2).reshape(
    batch_size,
    num_tokens,
    self.num_heads * self.head_dim,
)

return self.out_proj(context)

After transpose(1, 2), each sequence and each attention head has its own token-by-token attention calculation. The batch items never attend to one another; they are simply processed in parallel.

The causal mask still has shape (tokens, tokens). PyTorch broadcasts it across every batch item and attention head, so the same look-ahead rule applies throughout the batch.

3. Return logits for every position

The inference-only model selects the final token vector before applying the vocabulary projection. Training instead projects the complete sequence:

def forward(self, token_ids):
    if token_ids.ndim != 2:
        raise ValueError(
            "token_ids must have shape (batch_size, sequence_length)"
        )
    if token_ids.size(1) == 0:
        raise ValueError("each sequence must contain at least one token")

    x = self.embedding(token_ids)

    for block in self.transformer_blocks:
        x = block(x)

    x = self.final_norm(x)

    # Training needs a next-token prediction at every input position.
    return self.vocabulary_projection(x)

The result has shape (batch, tokens, vocabulary). At each batch item and token position, there is one logit for every possible next token.

Generation still needs only the last position of one prompt, so the inference code selects it after running the model:

with torch.inference_mode():
    all_logits = model(token_ids)
    next_token_logits = all_logits[0, -1]

0 selects the single prompt in the batch, and -1 selects its final position. This lets one model implementation support both batched training and ordinary next-token generation.
