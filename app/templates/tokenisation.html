Tokenisation, Step by Step

Tokenisation is the bridge between human text and the integer IDs a language model can process. It slices text into reusable pieces, then replaces each piece with an ID from a fixed vocabulary.

Modern LLM tokenizers are usually sub-word tokenizers. Common words can be single tokens, while uncommon words, names, code, and punctuation can be split into smaller chunks.

The process at a glance

Step 1 — split the text into rough pieces

Suppose the prompt is “The tokeniser re-tokenised pdlawson.com!”. A tokenizer first separates broad patterns such as words, leading spaces, punctuation, and byte-level fallbacks.

The tokeniser re-tokenised pdlawson.com!

Step 2 — use sub-word pieces for rare text

Vocabulary space is limited. Instead of storing every possible word, a tokenizer stores frequent chunks that can be recombined. That is why tokenisation, tokeniser, and re-tokenised can share pieces.

Step 3 — map each token to an ID

After splitting, each token is just a vocabulary entry. The model receives IDs, not strings. Spaces often belong to the token that follows them, which lets the model distinguish dog from dog.

Why this matters: token count controls context length, latency, and cost. A sentence that looks short to a human can become many tokens if it contains unusual names, URLs, emojis, or code.

Minimal implementation

A tokenizer API used by the app only needs to return the pieces and IDs:

def tokenise(text, encoding):
    token_ids = encoding.encode(text)
    tokens = [encoding.decode([token_id]) for token_id in token_ids]
    return {"tokens": tokens, "token_ids": token_ids}
