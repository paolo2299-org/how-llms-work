Pre-training starts with a large body of text, but this model does not accept raw text. We first turn the entire text into one stream of token IDs using the same tokenizer that will later process prompts.

The important preparation step is then to make many examples in which one sequence of tokens is the input and the same sequence, shifted one position to the left, is the target. Each target token is therefore the correct next token for the corresponding input position.

Build shifted input and target sequences

Our training implementation puts this logic in NextTokenDataset:

class NextTokenDataset(Dataset):
    """Split text into fixed-length input and target sequences."""

    def __init__(self, text, sequence_length):
        self.token_ids = torch.tensor(tokenise(text), dtype=torch.long)
        self.sequence_length = sequence_length

        # Each target is the corresponding input shifted one token to the left.
        # Non-overlapping starts keep this example small and easy to inspect.
        self.start_positions = list(
            range(
                0,
                len(self.token_ids) - sequence_length,
                sequence_length,
            )
        )

        if not self.start_positions:
            raise ValueError(
                "the input text must contain more tokens than sequence_length"
            )

    def __len__(self):
        return len(self.start_positions)

    def __getitem__(self, index):
        start = self.start_positions[index]
        stop = start + self.sequence_length
        inputs = self.token_ids[start:stop]
        targets = self.token_ids[start + 1 : stop + 1]
        return inputs, targets

If a sequence has four input tokens, the dataset needs five consecutive tokens from the full stream. The first four become the input and the last four become the target:

One shifted training sequence
Position 0 1 2 3
Input t0 t1 t2 t3
Target t1 t2 t3 t4

At position 0 the model is asked to predict t1 from t0. At position 1 it predicts t2 after seeing t0, t1, and so on. The causal attention mask prevents each position from looking ahead at the target it is supposed to predict.

Why is one extra token required? A sequence of 16 inputs needs a 17th token to provide the final target. That is why the range stops at len(self.token_ids) - sequence_length rather than at the end of the token stream.

Group sequences into batches

The dataset returns one fixed-length input/target pair at a time. A PyTorch DataLoader groups several pairs so the model can process them together:

def create_data_loader(text_path, sequence_length, batch_size):
    text = Path(text_path).read_text(encoding="utf-8")
    dataset = NextTokenDataset(text, sequence_length)
    return DataLoader(dataset, batch_size=batch_size, shuffle=True)
Shapes created by the dataset and data loader
Value Shape Meaning
One input sequence (tokens,) One fixed-length window from the token stream
One target sequence (tokens,) The input window shifted by one token
One input batch (batch, tokens) Several input windows stacked together
One target batch (batch, tokens) The matching target for every input position

shuffle=True changes the order of the fixed-length sequences on each pass through the dataset. It does not shuffle the tokens inside a sequence, because their order is exactly what the model needs to learn.

The teaching implementation deliberately uses non-overlapping windows and drops any final incomplete window. Production datasets often use more sophisticated packing and sampling, but the input/target shift is the same.
