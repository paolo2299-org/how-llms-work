Feed-Forward Layer, Step by Step

Self-attention lets tokens exchange information. The feed-forward layer that follows does something deliberately different: it processes each enriched token independently, using the same small neural network for every token in the sequence.

We will continue directly from the five-token example on the multi-head attention page. Its output has six values per token, so our feed-forward layer will expand each token from 6 dimensions to 12, apply a non-linear activation, then project it back to 6 dimensions.

The shape of the layer

A feed-forward layer is often called a position-wise MLP. “Position-wise” means that every row is transformed separately; unlike attention, this operation never combines one token's row with another token's row. “MLP” means that it contains more than one linear layer, with a non-linear activation between them.

The complete setup below uses torch.manual_seed(42), so PyTorch initialises the two linear layers with the same weights every time. That makes every number on this page reproducible. The tables round values to four decimal places; PyTorch keeps full precision during the calculations.

import torch
import torch.nn as nn


x = torch.tensor([
    [0.25, -0.69, -0.03,  0.00,  0.09, 0.12],
    [0.15, -0.61, -0.18, -0.33, -0.24, 0.31],
    [0.06, -0.36, -0.15, -0.14, -0.06, 0.13],
    [0.04, -0.38, -0.16, -0.12, -0.02, 0.14],
    [0.11, -0.38, -0.04, -0.09, -0.04, 0.19],
])

torch.manual_seed(42)
expand   = nn.Linear(6, 12)  # includes a learned bias
activate = nn.GELU()
project  = nn.Linear(12, 6)  # includes a learned bias

Step 1 — expand each token

The first linear layer applies x @ weight.T + bias. Its weight has shape (12, 6): twelve learned feature rows, each looking at all six values in a token. The same weight and bias are used for every token.

expanded = expand(x)

print(expand.weight.shape)  # torch.Size([12, 6])
print(expand.bias.shape)    # torch.Size([12])
print(expanded.shape)       # torch.Size([5, 12])

For example, the first number produced for the₁ is the dot product of that token's six values and the first row of the weight, plus the first bias:

Step 2 — apply GELU

If we stacked two linear layers without an activation between them, the pair would still behave like a single linear layer. GELU introduces the non-linearity that lets the network learn more complicated features.

activated = activate(expanded)
print(activated.shape)  # torch.Size([5, 12])

GELU smoothly scales each number using GELU(z) = 0.5z(1 + erf(z / √2)). For the value we just calculated:

GELU(0.2418) = 0.5 × 0.2418 × (1 + erf(0.2418 / √2))
             = 0.1440

Positive values tend to pass through, while negative values are usually reduced towards zero rather than being cut off abruptly. The activation changes the values but not their shape:

The twelve hidden values can be thought of as learned feature activations. Some may line up with concepts people can name, but real models also use distributed and overlapping representations: a useful concept does not have to live in exactly one hidden unit.

Step 3 — project back to the embedding width

The second linear layer combines the twelve activated features into six output values per token. Its weight therefore has shape (6, 12).

output = project(activated)

print(project.weight.shape)  # torch.Size([6, 12])
print(project.bias.shape)    # torch.Size([6])
print(output.shape)          # torch.Size([5, 6])

The layer has changed every token, but the sequence shape is back to (5, 6). That matching width is what allows the transformer to add this result back to the layer's input through a residual connection.

Every token is processed independently

All five rows can be calculated together because PyTorch batches the matrix operations, but the result for a token does not depend on any other row. Processing dog alone gives exactly the same result as taking its row from the full sequence:

dog_alone = project(activate(expand(x[1])))

torch.allclose(dog_alone, output[1])  # True

This is the key contrast: self-attention mixes information between token positions; the feed-forward layer then transforms the features within each position.

Full implementation

Putting the three operations together gives a complete feed-forward layer:

import torch.nn as nn


class FeedForward(nn.Module):

    def __init__(self, embed_dim, hidden_dim):
        super().__init__()
        self.expand = nn.Linear(embed_dim, hidden_dim)
        self.activation = nn.GELU()
        self.project = nn.Linear(hidden_dim, embed_dim)

    def forward(self, x):
        return self.project(self.activation(self.expand(x)))

nn.Linear always operates on the final dimension, so this class works without modification for either a single sequence or a batch of sequences:

ffn = FeedForward(embed_dim=6, hidden_dim=12)

ffn(torch.randn(5, 6)).shape     # torch.Size([5, 6])
ffn(torch.randn(2, 5, 6)).shape  # torch.Size([2, 5, 6])

LayerNorm and the residual connection belong to the surrounding transformer block, not to the feed-forward layer itself. In a pre-normalised transformer, that surrounding operation is conceptually:

x = x + feed_forward(layer_norm(x))

Many modern LLMs use a gated feed-forward variant such as SwiGLU instead of this classic GELU MLP. The details differ, but the central shape story remains the same: widen each token into a feature space, apply a non-linear transformation, then project it back to the embedding width.
