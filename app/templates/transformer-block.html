Transformer Block

A transformer block is the reusable unit that makes the representations inside an LLM more useful. Each block takes a sequence of token vectors, lets the tokens communicate through attention, processes each token through a feed-forward layer, and returns a sequence with the same shape.

On this page we will use the same five-token, six-dimensional example from the multi-head attention and feed-forward walkthroughs. The important new pieces are LayerNorm and residual connections, which wrap those two processing stages.

The whole block at a glance

Our input

We begin with five contextual token vectors. In a real LLM the width might be thousands of dimensions; here it is six so the numbers fit on the page.

input x — shape (5, 6)
012345
the₁0.25-0.69-0.030.000.090.12
dog0.15-0.61-0.18-0.33-0.240.31
fetched0.06-0.36-0.15-0.14-0.060.13
the₂0.04-0.38-0.16-0.12-0.020.14
ball0.11-0.38-0.04-0.09-0.040.19

Step 1 — normalise before attention

LayerNorm works across the features of one token at a time. For each row, it subtracts that row's mean and divides by that row's standard deviation, then applies learned scale and shift parameters.

mean(the₁) = (0.25 - 0.69 - 0.03 + 0.00 + 0.09 + 0.12) / 6 = -0.0433
norm(the₁, feature 0) = (0.25 - (-0.0433)) / std(the₁)

This gives attention a steadier input distribution. In modern decoder-only LLMs this is commonly done in pre-norm form: normalise first, run the sub-layer second, then add the unnormalised input back in.

Step 2 — multi-head attention adds context

The normalised vectors go into multi-head attention. Attention is the only part of this block where rows directly exchange information: each token chooses a weighted mix of the previous token representations.

For a decoder-only language model, attention uses a causal mask. A token can look at itself and earlier tokens, but not future tokens. The output shape is still (5, 6).

Step 3 — add the first residual connection

Instead of replacing x with the attention result, the block adds the attention result to the original input:

x = x + attention(norm1(x))

This residual connection means the attention layer only has to learn a useful change. If attention has nothing helpful to add for a feature, the original value can pass through unchanged.

Step 4 — normalise again, then use the feed-forward layer

The partially updated sequence is normalised again and passed through the feed-forward network. Unlike attention, the feed-forward layer processes each token position independently. It widens each token into a hidden feature space, applies a non-linearity, and projects back to the embedding width.

hidden = norm2(x)
change = feed_forward(hidden)  # shape remains (5, 6)

Step 5 — add the second residual connection

The feed-forward change is added back to the sequence from the attention half of the block:

x = x + feed_forward(norm2(x))

At this point one block is complete. The output still has shape (5, 6), but each row has been refined by both context mixing and per-token feature processing.

Full implementation

Putting the two wrapped sub-layers together gives the standard shape of a pre-normalised transformer block:

import torch.nn as nn


class TransformerBlock(nn.Module):

    def __init__(self, embed_dim, num_heads, hidden_dim):
        super().__init__()
        self.norm1 = nn.LayerNorm(embed_dim)
        self.attention = MultiHeadAttention(embed_dim, num_heads)
        self.norm2 = nn.LayerNorm(embed_dim)
        self.feed_forward = FeedForward(embed_dim, hidden_dim)

    def forward(self, x):
        x = x + self.attention(self.norm1(x))
        x = x + self.feed_forward(self.norm2(x))
        return x

Why LayerNorm?

It keeps each token vector on a predictable scale before a sub-layer tries to process it, which makes deep stacks easier to train.

Why residuals?

They preserve existing information and give gradients a short route backwards through many stacked blocks.
