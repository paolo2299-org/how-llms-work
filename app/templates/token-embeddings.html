Token Embeddings, Step by Step

Token embeddings turn token IDs into vectors: lists of learned numbers that a neural network can transform. If tokenisation says which vocabulary item appeared, the embedding says how that item starts its journey through the model.

On this page we use six-dimensional vectors so the tables fit. Real LLMs often use thousands of dimensions.

The lookup at a glance

Step 2 — look up token vectors

Each ID selects one row from the learned token embedding table. Tokens that appear in similar contexts are pushed toward useful geometric relationships during training.

Step 3 — add position embeddings

The same token can appear in different places. A position embedding tells the model where each token sits in the sequence. The model adds token and position vectors element by element.

x[position] = token_embedding[token_id] + position_embedding[position]
# for five tokens and six features, x has shape (5, 6)

Important distinction: the simple 3D demo on the main page visualises semantic word embeddings. LLM token embeddings are learned as part of the language model itself and may encode syntax, position-sensitive usage, and model-internal features as well as meaning.

Minimal implementation

In a neural-network library, token embeddings and position embeddings are usually two learned lookup tables:

class TokenAndPositionEmbeddings(nn.Module):
    def __init__(self, vocab_size, max_seq_len, embed_dim):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, embed_dim)
        self.position_embedding = nn.Embedding(max_seq_len, embed_dim)

    def forward(self, token_ids):
        positions = torch.arange(token_ids.shape[-1], device=token_ids.device)
        return self.token_embedding(token_ids) + self.position_embedding(positions)
