For every input position, the model produces one logit for every token in its vocabulary. The matching target batch tells us which token should have received the strongest score at each position.

Training turns that comparison into a single loss value, calculates how changing every weight would affect the loss, and then lets an optimiser update the weights.

  1. ClearRemove gradients left by the previous batch
  2. PredictRun the input batch through the model
  3. MeasureCompare every position with its target
  4. BackpropagateCalculate a gradient for every weight
  5. UpdateLet AdamW adjust the weights

Turn all predictions into one loss

The model’s logits have three axes: (batch, tokens, vocabulary). PyTorch cross-entropy expects a two-dimensional collection of predictions and one target ID for each prediction, so the training code combines the batch and token axes:

logits = model(inputs)
loss = F.cross_entropy(
    logits.flatten(0, 1),
    targets.flatten(),
)
Shapes passed to cross-entropy
Value Before flattening After flattening
Logits (batch, tokens, vocabulary) (batch × tokens, vocabulary)
Target token IDs (batch, tokens) (batch × tokens)

Each flattened row of logits is still paired with exactly the same target token as before. Flattening changes only the layout expected by the loss function; it does not mix predictions and targets.

Why no softmax? F.cross_entropy accepts raw logits and performs the required log-softmax calculation internally. Applying softmax first would be redundant and less numerically stable.

Cross-entropy gives a larger loss when the correct token receives a low score and a smaller loss when it receives a high score. By default, PyTorch averages the loss across all batch × tokens predictions.

Backpropagation and AdamW do different jobs

Backpropagation does not update a weight or assign it a share of blame. It calculates the gradient of the loss with respect to that weight: how a small change to the weight would change the loss at the model’s current state.

The optimiser then uses those gradients to choose and apply the updates. Our implementation uses AdamW:

model.to(device)
model.train()
optimiser = torch.optim.AdamW(model.parameters(), lr=learning_rate)

for epoch in range(epochs):
    total_loss = 0.0

    for inputs, targets in batches:
        inputs = inputs.to(device)
        targets = targets.to(device)

        optimiser.zero_grad()
        logits = model(inputs)
        loss = F.cross_entropy(
            logits.flatten(0, 1),
            targets.flatten(),
        )
        loss.backward()
        optimiser.step()

        total_loss += loss.item()

Each line has a distinct role:

  • optimiser.zero_grad() clears old gradients, because PyTorch accumulates gradients unless asked to reset them.
  • model(inputs) performs the forward pass and records the operations needed for differentiation.
  • loss.backward() runs backpropagation and stores a gradient on every parameter that contributed to the loss.
  • optimiser.step() uses those gradients, AdamW’s running statistics, the learning rate, and weight decay to update the parameters.

The learning rate controls the overall scale of the updates. AdamW adapts individual updates using recent gradient behaviour, while its decoupled weight decay gently discourages weights from growing without bound.

Monitor the training loss

After each pass through the dataset, the teaching script prints the average loss across its batches:

average_loss = total_loss / len(batches)
print(f"Epoch {epoch + 1}: loss = {average_loss:.4f}")

This number is useful for confirming that optimisation is working, but it is the loss on the training batches. A larger training system would normally also evaluate held-out validation data and use additional monitoring and checkpointing.

The included script is intentionally direct: one optimiser, one loss, and a fixed number of epochs. Techniques such as learning-rate schedules, gradient clipping, mixed precision, and distributed training are useful at larger scales, but they do not change the core sequence shown here.
